# MVP-43 — Matriz de aceptación y brechas del SRS

Fecha: 31 de octubre de 2026. TARGET de esta revisión: `6cceee1cb93f80b978a20c95ad859337ea1b1026`.
Baseline: [SRS v0.1](../Documentos%20SRS/SRS.md), borrador del 15 de octubre. No se modifica ni se da por aprobado el SRS.

## 1. Qué mide esta revisión

Se contrastan **13 RF, 9 RNF y 12 CA** con código y pruebas del repositorio. Es una
auditoría documental y estática apoyada en resultados anteriores, no una nueva
ejecución de aceptación ni una revisión de seguridad del entorno de producción.

- **VERIFICADO_LOCAL**: hay implementación y aserciones pertinentes para el comportamiento indicado en el entorno sintético local. No significa universalidad ni aprobación del producto.
- **PARCIAL**: existe trabajo verificable, pero falta una cláusula, una decisión necesaria o evidencia suficiente para cerrar esa fila.
- **SIN_EVIDENCIA**: no se ha encontrado evidencia pertinente. No se usa para negar pruebas existentes porque aún no haya despliegue.
- **Aceptación formal**: pendiente para las tres familias; no se encontró una aprobación global del SRS y sus presupuestos. Es una dimensión distinta del estado técnico de las tablas.

Una fila VERIFICADO_LOCAL describe los formatos, límites y escenarios documentados,
no todos los protocolos o entradas imaginables. Las brechas son trabajo o decisiones
pendientes, **no vulnerabilidades demostradas**. Los nombres de pruebas citados son
métodos existentes, incluyendo teorías con varios casos; no son casos nuevos de MVP-43.

| Familia | VERIFICADO_LOCAL | PARCIAL | SIN_EVIDENCIA | Filas |
| --- | ---: | ---: | ---: | ---: |
| RF | 8 | 5 | 0 | 13 |
| RNF | 4 | 5 | 0 | 9 |
| CA | 9 | 3 | 0 | 12 |

Estos conteos **no son un porcentaje de proyecto**: los CA se solapan con RF/RNF,
las filas tienen tamaños y riesgos diferentes y no se han acordado pesos de esfuerzo.
La estimación conversacional previa de aproximadamente 70% ±10 no tenía ese modelo
de medición y no se utiliza como indicador de aceptación. No se asigna medio punto a
lo parcial ni se usa el número de pruebas o de MVP como progreso.

- Suite .NET completa ejecutada el **30 de octubre**: **1474/1474 PASS**, cero omitidos. Se cotejaron counters y los 1474 resultados individuales del TRX durante esta revisión.
- Comando histórico: `dotnet test ProyectoSeguridad.slnx -c Release --no-restore --logger "trx;LogFileName=full.trx" --results-directory <scratch>/full`.
- Artefacto local no publicado: `memory-body-fix/full/full.trx` bajo Temp/opencode. SHA-256: `CEAA3A3D8EAF61D4DE8229DBF1737AEC6AAC12D0D8ED3C787DC6687083EE08F5`.
- No hubo cambios versionados a hosts, arneses, referencias de dependencias, configuración o tests .NET después de su evidencia final. El test de resiliencia OTLP, entonces no versionado, coincide con el hash comprobado: `8373EE6E41F4B00469FD1E6B1DC980D42EF34670B81C312A167F16B86951BD66`. Su publicación fue `4873a0cb18be59e902e1889a4a63624f8f366142`; desde ese commit al TARGET la zona .NET no cambió. El hash no prueba comportamiento por sí solo: permite vincular el contenido a la ejecución previa. No se acredita con esto una nueva ejecución ni un entorno futuro idéntico.
- MVP-41 añade pruebas reproducibles de ciclo de vida y MVP-42 observó límites de retención local. Se documentan en [README](../README.md); no prueban por sí solos RF-11/RNF-07 completos. El harness MVP-42 permanece como artefacto local, no un comando disponible en un clone limpio.

### Reproducción en un clon preparado

Usar el SDK fijado en [global.json](../global.json), datos sintéticos y puertos locales
disponibles. Inspeccionar proyectos y destinos antes de ejecutar. Desde la raíz:

```powershell
dotnet restore ProyectoSeguridad.slnx
dotnet test ProyectoSeguridad.slnx -c Release --no-restore --logger "trx;LogFileName=acceptance.trx" --results-directory artifacts/mvp43-acceptance
```

Estos comandos son instrucciones de reproducción, **no ejecución realizada en
MVP-43**. Un resultado nuevo debe registrar commit, política, SDK/entorno, comando,
resultados individuales y su aprobación. La ejecución local previa no obliga a
un tercero a confiar en un TRX que no se distribuye: las fuentes y pruebas están
enlazadas para inspección y reproducción. No ejecutar carga o piloto contra
infraestructura no autorizada.
